# `alert` — registry entry

The artefacts `primitiv add alert` resolves and copies into a consumer repo —
a banner for high-priority, time-sensitive messages. Composes the headless
[`Alert`](../../../packages/react/src/Alert/README.md) primitive (`role="alert"`)
for the live-region message and the registry [`Button`](../button/README.md)
(`ghost` variant) for the dismiss affordance.

## What it does

`Alert` renders a `<div role="alert">` containing a tone-matched leading icon,
an optional title, a required description, and an optional dismiss button.
Four tones, sized `xs`–`xl` (default `md`); `data-density` scales each size
further.

| Tone | Default icon | Typical use |
|---|---|---|
| `info` (default) | info circle | general notices |
| `success` | check | confirmations |
| `warning` | triangle | caution, non-blocking issues |
| `danger` | x-circle | errors, destructive-action confirmations |

## Usage

```tsx
import { Alert } from "@/components/alert";

<Alert tone="danger" title="Payment failed">
  Your card was declined. Try a different payment method.
</Alert>

{/* Single-message alert — no title */}
<Alert tone="success">Changes saved.</Alert>

{/* Dismissible — the dismiss button only renders when onDismiss is passed */}
<Alert onDismiss={() => setVisible(false)}>New version available.</Alert>

{/* Custom icon */}
<Alert icon={<CustomGlyph />}>A message with a bespoke icon.</Alert>
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-alert` root class, the `tone`/`size` modifiers, and the `--primitiv-alert-*` custom properties. |
| `styles.css` | **authored** | The canonical default theme: the banner layout + tone colour matrix + dismiss-button colour overrides, in `@layer primitiv.base`/`primitiv.variants`/`primitiv.states`. |
| `styles.scss` | **authored** | `styles.css` plus a trailing `$`-alias block, one `$primitiv-alert-<prop>` per custom property. |
| `alert.recipe.ts` | **authored** | `cva("primitiv-alert", { variants: { tone, size } })` — mirrors `tag`'s recipe shape. |
| `alert.tsx` | **authored** | The `<Alert>` wrapper — composes the headless `Alert` primitive and the registry `Button`. |

Because the icon/title/description/dismiss anatomy has no generator-emitted
shape, `alert.tsx`/`alert.recipe.ts` are **not** generated by `primitiv-emit`
and carry **no drift-guard test** (contrast the generated wrappers, D53).
`alert.tsx` is type-checked in CI by `scripts/check-registry-types.mjs` like
every other registry wrapper.

## Tokens

`alert` reuses Badge/Tag's `feedback/{tone}/soft/{background,foreground}`
Intent tokens directly, plus two more from the same family for the dismiss
button's interaction states — `feedback/{tone}/soft/{hover,active}`, one and
two steps further from the background toward the foreground respectively
(light mode: background 100 → hover 200 → active 300; dark mode: background
100 → hover 200 → active 300, the same steps as light — every
`feedback/{tone}/soft/*` property names one ramp step and lets the
independently-authored dark ramp do the inverting, not a different step per
theme; see `packages/tokens/README.md`'s "Dark mode: this repo and Figma
encode it oppositely"). Alert also carries a **border**, matching the tone's
foreground colour: `--primitiv-alert-border-color` defaults to
`feedback/{tone}/soft/border` (a fourth property in the same family, sharing
the border/foreground alias — a tone's border and text are always the same
colour) and `--primitiv-alert-border-width` to the shared
`framed-control/border-width`. Sizing reuses
`framed-control/{size}/{padding-inline,gap,icon-size,radius}` directly (a
bordered — well, borderless — icon-led box, like Chip), plus two
Alert-specific Context tokens `alert/{size}/padding-block` (block padding a
single-row framed control doesn't need) and `alert/{size}/icon-offset-top`
(nudges the icon down so its visual top aligns with the title's cap-height,
compensating for the leading space in the title's line-box that the icon's
own tight bounding box doesn't have — the classic icon-vs-heading optical-
alignment issue). Title type is `label/{size}/*` (Khand SemiBold); description
type is `body/{size}/*` (Asta Sans Regular).

## Notes

- **The dismiss button is a real `Button`, not a bespoke element.** It
  co-classes Button's own `ghost` variant (`.primitiv-alert__dismiss`
  alongside `.primitiv-button.primitiv-button--ghost`) so it inherits
  Button's height/padding/radius/focus-ring/transitions verbatim — Alert's
  stylesheet only re-points the two custom properties Button already reads
  (`--primitiv-button-fg`/`--primitiv-button-bg`), sourced from Alert's own
  tone-repointed tokens rather than duplicating them. This mirrors how
  Modal's canonical close button composes a ghost `Button` around a `Close`
  icon — Alert just does the composition internally instead of leaving it to
  the consumer, since `onDismiss` is a prop on `Alert` itself.
- **The dismiss button is same-sized, not stepped down.** Unlike Modal's
  close button (one size step below the dialog, since it sits next to a
  separate Title), Alert's dismiss uses the same `size` as the alert itself
  — matching the Figma "Alert" component set, where the nested Icon Button
  instance is `Size={size}` throughout.
- **Icon is always shown, tone-determined by default, overridable.** There is
  no "show icon" toggle (unlike `Show title`/dismiss's `onDismiss` presence)
  — pass `icon` to swap the glyph per instance, matching the Figma set's
  per-Tone `INSTANCE_SWAP` properties (four separate properties there, since
  a single shared property can't carry four different per-Tone defaults —
  same constraint Badge's Label/Counter split hit).
- **Title is optional, description is required.** The headless `Alert`
  primitive's own simplest usage is a single message with no heading
  (`<Alert>{error}</Alert>`) — `title` renders only when passed.
- **No `asChild`.** Unlike `Tag`/`Badge` (simple single-element leaves),
  `Alert`'s children prop is the description, not an arbitrary passthrough
  target — the multi-part icon/content/dismiss anatomy doesn't compose with
  `asChild` the way a single wrapping element does (same reasoning as
  `Chip`, the other compound hand-authored leaf).
