# `chip` — registry entry

The artefacts `primitiv add chip` resolves and copies into a consumer repo —
the **interactive, removable label chip** from RFC 0021. Like `code-block`,
`chip` has **no headless `@primitiv-ui/react` counterpart**: it carries real
behaviour (a remove button, its own hover/active/focus styling), but no
composed primitive, so it ships entirely from the registry.

## What it does

`Chip` renders `[leading icon?][label][remove button]` — used in filter
bars, multi-select fields, and inputs. The trailing remove button is **core
to the anatomy, not optional** (a design decision made explicit on the
Figma "Chip" component set's rough exploration); a leading icon or avatar is
optional. Sized `xs`–`xl` (default `md`); `data-density` scales each size
further.

Unlike `Badge`/`Tag`, a Chip is **genuinely interactive**, so it reuses
`framed-control/{size}/*` sizing and `action/secondary/*` fill/stroke/
foreground directly — the same neutral bordered look `Button`'s secondary
variant uses — rather than a dedicated token family, with a `radii/full`
pill-radius override.

## Usage

```tsx
import { Chip } from "@/components/chip";
import { User } from "@primitiv-ui/icons";

<Chip onRemove={() => removeFilter("status")}>Status: Active</Chip>
<Chip leadingIcon={<User />} onRemove={() => removeAssignee()}>Jane Doe</Chip>
<Chip disabled onRemove={() => {}}>Locked</Chip>
```

`onRemove` is required — removability is core to a Chip's anatomy. Reach for
`Tag` instead when a chip doesn't need to be removable.

## Accessibility

The root `<span>` is not itself clickable or focusable, which avoids a
nested-interactive-element problem: only the trailing remove `<button>` is a
real interactive element. Its `aria-label` defaults to `` `Remove ${children}` ``
when the label is a plain string, or `"Remove"` otherwise — pass
`removeLabel` to override. `disabled` disables the remove button
(`<button disabled>`) and dims the whole chip via a CSS `:has()` selector
keyed off that button's own `:disabled` state.

## Interaction states

Only the remove button is a real interactive/focusable element, but the
Interaction styling is drawn on the *whole pill*:

- **hover** — `:hover` on the chip root directly (the whole pill is the
  natural hover target), gated behind `@media (hover: hover)`.
- **active** — `.primitiv-chip:has(.primitiv-chip__remove:active)` — only
  the remove button itself is pressable.
- **focus** — `.primitiv-chip:has(.primitiv-chip__remove:focus-visible)`
  draws the shared two-layer focus ring (the same box-shadow technique every
  other framed control uses) on the *root*, so the ring wraps the whole
  chip rather than just the small remove icon — even though the button is
  what actually receives focus. The button's own default outline is
  suppressed (`outline: none`) since the root carries the ring.
- **disabled** — `.primitiv-chip:has(.primitiv-chip__remove:disabled)`,
  ordered last in `primitiv.states` so it always wins over hover/active.

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-chip` root class, the `__leading-icon`/`__label`/`__remove` parts, the `size` modifier, and the `--primitiv-chip-*` custom properties. |
| `styles.css` | **authored** | The canonical default theme: the pill box, icon/label/remove parts, and the hover/active/focus/disabled states, in `@layer primitiv.base`/`primitiv.variants`/`primitiv.states`. |
| `styles.scss` | **authored** | `styles.css` plus a trailing `$`-alias block, one `$primitiv-chip-<prop>` per custom property. |
| `chip.recipe.ts` | **authored** | `cva("primitiv-chip", { variants: { size } })`. |
| `chip.tsx` | **authored** | The `<Chip>` wrapper. Hand-written (there is no primitive to generate from): renders the leading-icon slot, label, and remove button; the remove glyph is inlined from `@primitiv-ui/icons`' `Close`, matching `code-block`'s Copy/Check glyphs, so the component installs no extra package. |

Because there is no headless primitive, `chip.tsx`/`chip.recipe.ts` are
**not** generated by `primitiv-emit` and carry **no drift-guard test**
(contrast the generated wrappers, D53). `chip.tsx` is type-checked in CI by
`scripts/check-registry-types.mjs` like every other registry wrapper.

## Tokens

`chip` is the one member of the Badge/Tag/Chip trio that reuses existing
token families wholesale rather than adding a dedicated one:

- **`action/secondary/*`** (Intent) — the same neutral bordered fill/stroke/
  foreground family Button's secondary variant and ToggleGroup Item's off
  state use.
- **`framed-control/{size}/{height,padding-inline,gap,icon-size}`** (Context)
  — reused directly, no `chip/*` family.
- **`radii/full`** — overrides `framed-control/{size}/radius` for the pill
  shape.
- **`framed-control/border-width`**, **`focus/ring`** /
  **`focus/ring/width`** / **`focus/ring/offset`** — the standard framed-
  control border and focus-ring tokens.
- **`label/{size}/*`** — the label typography (Khand SemiBold), matching
  Button's own control-label type.
