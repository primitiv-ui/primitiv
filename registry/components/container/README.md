# `container` — registry entry

The artefacts `primitiv add container` resolves and copies into a consumer
repo — the centred content-column primitive from RFC 0022 (build-order step 3).
Like `box`/`center`, `container` has **no headless `@primitiv-ui/react`
counterpart**: `<Container>` carries zero behaviour, so it ships entirely from
the registry.

## What it does

`Container` centres a content column, caps its width, and pads its inline
edges. It is the piece that turns a full-width page into a readable column —
the thing every consumer previously hand-rolled.

- `size` — `"xs"`–`"2xl"` or `"full"` (default `"lg"`). The width cap,
  resolved **straight against the breakpoint scale** (RFC 0025) rather than a
  container-specific width scale, so `size="lg"` stops growing exactly where
  the `lg` breakpoint begins. `"full"` removes the cap entirely.
- `gutter` — `"responsive"` (default), `"none"`, or a pinned `"sm"`/`"md"`/
  `"lg"`. `responsive` uses the small gutter on narrow viewports and steps up
  at `md` and again at `lg`, so edge padding grows with the room available
  instead of staying phone-sized on a desktop.
- `asChild` — render your own element (`<main>`, `<section>`, ...) instead of the
  wrapping `<div>`.

`box-sizing` is `border-box`, so the gutter sits **inside** the cap: at
`size="lg"` the column measures 64rem edge to edge and the content area is
what remains. This matches Tailwind's and Chakra's containers.

### Full-bleed is two knobs, not one

`size="full"` drops the width cap but **keeps** the gutters — a full-width band
with readable edges, which is what "full bleed" usually means in a page layout.
`gutter="none"` drops the padding. True edge-to-edge is both together:

```tsx
<Container size="full" gutter="none">
  <img src="/hero.jpg" alt="" />
</Container>
```

### There is no `centerContent` prop

Chakra's Container has one; this one does not. `Container` centres *itself*;
centring content *within* it is `<Center>`'s job, and composing the two is the
system's existing answer:

```tsx
<Container>
  <Center>...</Center>
</Container>
```

## Usage

```tsx
import { Container } from "@/components/container";

<Container>
  <Prose>...</Prose>
</Container>

<Container size="xl" asChild>
  <main>...</main>
</Container>

<Container size="md" gutter="lg">
  <article>...</article>
</Container>
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-container` root class, the `--xs`...`--2xl`/`--full` and `--gutter-*` modifiers, and the two custom properties. |
| `styles.css` | **authored** | The canonical default theme: the cap/centre/pad rules in `@layer primitiv.base`, the size and gutter modifiers in `primitiv.variants`. |
| `styles.scss` | **authored** | Byte-identical mirror of `styles.css` plus the `$primitiv-container-*` alias block. |
| `container.recipe.ts` | **authored** | `cva("primitiv-container", { variants: { size, gutter } })`. |
| `container.tsx` | **authored** | The `<Container>` wrapper. Hand-written (there is no primitive to generate from): a thin `asChild` (Slot) wrapper that renders a `<div>`, or the consumer's own element. |

Because there is no headless primitive, `container.tsx`/`container.recipe.ts`
are **not** generated by `primitiv-emit` and carry **no drift-guard test**
(contrast the generated wrappers, D53). `container.tsx` is type-checked in CI
by `scripts/check-registry-types.mjs` like every other registry wrapper.

## Tokens

| Token | Role |
|---|---|
| `--primitiv-breakpoint-{xs...2xl}` | The width caps. Referenced directly — no `container/max-width/*` family exists, deliberately (see below). |
| `--primitiv-container-gutter-{sm,md,lg}` | The gutter ramp — a density-scaled Context family, so the gutter re-tightens under `[data-density]`. |
| `--primitiv-space-space-0` | `gutter="none"`. Zero has no density curve to scale, so it pins the flat primitive directly. |

**Why the caps reference breakpoints directly.** A `container/max-width/*`
Context family would be the wrong collection — Context is density-scoped across
four modes, and a max-width should not tighten with density. Referencing the
breakpoint primitives keeps one source of truth and makes `size="lg"` mean
exactly "caps where `lg` begins".

## Custom properties

| Property | Defaults to |
|---|---|
| `--primitiv-container-max-width` | `var(--primitiv-breakpoint-lg)` |
| `--primitiv-container-gutter` | `var(--primitiv-container-gutter-sm)` |

To retheme the gutter ramp itself, override the three
`--primitiv-container-gutter-{sm,md,lg}` **tokens** in your theme layer rather
than the `--primitiv-container-gutter` knob — the responsive modifier re-points
that knob at each breakpoint, so setting it directly is overwritten above `md`.

## A note on the media queries

The `gutter="responsive"` escalation is written with **literal** `rem` values in
its `@media` conditions (`48rem`, `64rem`). This is deliberate and unavoidable:
a custom property cannot appear inside an `@media` condition — `@media
(min-width: var(--primitiv-breakpoint-md))` is not valid CSS (RFC 0025 §4). It
is a CSS-language limit, not a missing token, and the one exception to the
no-magic-numbers rule in this sheet. The values match
`--primitiv-breakpoint-{md,lg}` and the generated `breakpoints.ts` constant that
`primitiv tokens` emits beside the token layer; keep all three in step if the
scale ever moves.
