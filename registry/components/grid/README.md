# `grid` — registry entry

The artefacts `primitiv add grid` resolves and copies into a consumer repo —
the CSS Grid layout primitive from RFC 0022 (build-order step 3). Like
`box`/`center`/`container`, `grid` has **no headless `@primitiv-ui/react`
counterpart**: `<Grid>` carries zero behaviour, so it ships entirely from the
registry.

## No Figma counterpart

There is deliberately **no Figma component set** for this primitive, matching
`box`/`stack`/`spacer`/`center`/`aspect-ratio`. A grid's whole value is how it
reflows across widths, which a fixed-width Figma frame cannot express — a set
would be a static N-column frame that teaches a designer nothing. Auto-layout
already covers the static case natively. RFC 0022 is its whole spec, and the
`Figma` column of `ROADMAP.md` reads `—` for this reason. (`container` *does*
get a set, because a fixed max-width column is exactly what a design frame can
show.)

## What it does

- `columns` — a count (`3`) applied at every width, or a mobile-first map
  (`{ base: 1, md: 2, lg: 3 }`). `base` is the floor; each named tier applies
  from that breakpoint up. Defaults to a single column.
- `gap` — `"none"`/`"xs"`–`"xl"` (default `"md"`), a density-scaled Context
  token per step.
- `align` / `justify` — how each item sits **within its cell**
  (`align-items`/`justify-items`), from a curated preset set.
- `asChild` — render your own element (`<ul>`, `<section>`, ...) instead of the
  wrapping `<div>`.

### The responsive model

`columns` resolves to **modifier classes, never an inline style**, so the
responsive behaviour is pure CSS: correct in server-rendered markup on the
first paint, with no hydration flash and no JavaScript involved. `{ base: 1,
md: 2, lg: 3 }` becomes:

```
primitiv-grid--cols-1 primitiv-grid--md-cols-2 primitiv-grid--lg-cols-3
```

Tiers are mobile-first floors, not ranges (RFC 0025 D3), and the stylesheet
emits them in ascending order so the widest matching tier is the last rule to
apply and therefore wins.

The scale ships counts 1–6 across the six breakpoint tiers. For anything
outside that — a 7-column grid, a tier at some bespoke width — write one media
query against the escape hatch instead of reaching for a new class:

```css
@media (min-width: 90rem) {
  .my-gallery { --primitiv-grid-columns: 8; }
}
```

### Tracks are `minmax(0, 1fr)`, not `1fr`

A bare `1fr` track has an `auto` minimum, so a single child with long
unbreakable content (a code span, a long URL) pushes its track past its share
and blows the whole row out wider than the container. `minmax(0, 1fr)` gives
the track a zero minimum, so the child is clipped by its track instead. This is
the standard fix for the most common CSS Grid overflow surprise.

## Usage

```tsx
import { Grid } from "@/components/grid";

<Grid columns={{ base: 1, md: 2, lg: 3 }} gap="lg">
  <Card />
  <Card />
  <Card />
</Grid>

<Grid columns={{ base: 2, md: 4 }} gap="sm">
  {swatches.map((s) => <Swatch key={s.id} {...s} />)}
</Grid>

<Grid columns={3} gap="md" align="center" asChild>
  <ul>...</ul>
</Grid>
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-grid` root class, the `--cols-*`/`--{tier}-cols-*`/`--gap-*`/`--align-*`/`--justify-*` modifiers, and the two custom properties. |
| `styles.css` | **authored** | The canonical default theme: the grid/track rules in `@layer primitiv.base`, the column, gap and alignment modifiers in `primitiv.variants`. |
| `styles.scss` | **authored** | Byte-identical mirror of `styles.css` plus the `$primitiv-grid-*` alias block. |
| `grid.recipe.ts` | **authored** | `cva("primitiv-grid", { variants: { gap, align, justify } })`, plus the `gridColumns` helper. |
| `grid.tsx` | **authored** | The `<Grid>` wrapper. Hand-written (there is no primitive to generate from): a thin `asChild` (Slot) wrapper that renders a `<div>`, or the consumer's own element. |

Because there is no headless primitive, `grid.tsx`/`grid.recipe.ts` are **not**
generated by `primitiv-emit` and carry **no drift-guard test** (contrast the
generated wrappers, D53). `grid.tsx` is type-checked in CI by
`scripts/check-registry-types.mjs` like every other registry wrapper.

### Why `columns` is not a `cva` variant

`cva`'s variants are a `Record<string, string>` — one class per discrete prop
value. `columns` accepts an *object*, which that model cannot express, so it is
resolved by the exported `gridColumns` helper instead and the two class lists
are concatenated in `grid.tsx`. Everything else on the component is an ordinary
`cva` variant.

## Tokens

| Token | Role |
|---|---|
| `--primitiv-grid-gap-{xs,sm,md,lg,xl}` | The gap ramp — a density-scaled Context family, so the gap re-tightens under `[data-density]`. |
| `--primitiv-space-space-0` | `gap="none"`. Zero has no density curve to scale, so it pins the flat primitive directly. |

The `grid/gap-*` ramp deliberately mirrors `stack/gap-*` step for step, so a
Grid and a Stack at the same step line up when nested. If that duplication ever
needs collapsing, a shared `layout/gap-*` family is the obvious move.

## Custom properties

| Property | Defaults to |
|---|---|
| `--primitiv-grid-columns` | `1` |
| `--primitiv-grid-gap` | `var(--primitiv-grid-gap-md)` |

Every column rule re-points `--primitiv-grid-columns` rather than writing
`grid-template-columns` itself, which is what makes it a genuine escape hatch —
see "The responsive model" above.

## A note on the media queries

The per-tier column rules are written with **literal** `rem` values in their
`@media` conditions. This is deliberate and unavoidable: a custom property
cannot appear inside an `@media` condition — `@media (min-width:
var(--primitiv-breakpoint-md))` is not valid CSS (RFC 0025 §4). It is a
CSS-language limit, not a missing token, and the one exception to the
no-magic-numbers rule in this sheet. The values match `--primitiv-breakpoint-*`
and the generated `breakpoints.ts` constant that `primitiv tokens` emits beside
the token layer; keep all three in step if the scale ever moves.

## Deliberately not built

An intrinsic `minChildWidth` mode (`repeat(auto-fit, minmax(min(<token>, 100%),
1fr))`, Chakra's `SimpleGrid` behaviour) was scoped and **deferred** — it is a
second, mutually exclusive layout mode with its own precedence rules, and the
per-breakpoint `columns` map covers the cases that motivated this component.
Worth revisiting if container queries make an intrinsic grid the more natural
default.
