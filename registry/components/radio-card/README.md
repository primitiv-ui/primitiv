# `radio-card` — registry entry

The artefacts `primitiv add radio-card` resolves and copies into a
consumer repo — a card/tile-shaped radio item where the whole bordered
surface is the interactive element, not a small control plus a separate
label. Composes the headless
[`RadioCard`](../../../packages/react/src/RadioCard/README.md) primitive
(`RadioCard.Root` = `role="radiogroup"`, `RadioCard.Item` = `role="radio"`).

## What it does

`RadioCard` (the group wrapper) is a plain pass-through with no styling of
its own — `RadioCard.Root` carries no visual anatomy in the headless
layer, so there is nothing to style. `RadioCardItem` renders the actual
card: a persistent circular indicator (bordered, always visible — stays
light even when checked, per Radio's own convention; a centred dot appears
only when checked), a required title, and an optional description. Sized
`xs`–`xl` (default `md`); `data-density` scales each size further.
Exclusive selection — only one Item in a group can be checked.

## Usage

```tsx
import { RadioCard, RadioCardItem } from "@/components/radio-card";

<RadioCard defaultValue="pro" aria-label="Plan">
  <RadioCardItem value="starter" title="Starter" description="Free forever" />
  <RadioCardItem value="pro" title="Pro" description="$9/month" />
  <RadioCardItem value="enterprise" title="Enterprise" description="Contact us" />
</RadioCard>

{/* No description */}
<RadioCardItem value="basic" title="Basic" showDescription={false} />
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract for `RadioCardItem` — the `.primitiv-radio-card` root class, the `size` modifier, the `data-state`/`data-disabled` hooks, and the `--primitiv-radio-card-*` custom properties. `RadioCard` (the group) carries no contract of its own — it has no styling. |
| `styles.css` | **authored** | The canonical default theme: the card box + indicator + title/description type, in `@layer primitiv.base`/`primitiv.variants`/`primitiv.states`. |
| `styles.scss` | **authored** | `styles.css` plus a trailing `$`-alias block, one `$primitiv-radio-card-<prop>` per custom property. |
| `radio-card.recipe.ts` | **authored** | `cva("primitiv-radio-card", { variants: { size } })` — mirrors `checkbox-card`'s recipe shape. |
| `radio-card.tsx` | **authored** | `RadioCard` (a pure pass-through to the headless Root — see Dropdown/Modal for the same shape) and `RadioCardItem` (the styled card). |

Because the indicator/title/description anatomy has no generator-emitted
shape, `radio-card.tsx`/`radio-card.recipe.ts` are **not** generated by
`primitiv-emit` and carry **no drift-guard test** (contrast the generated
wrappers, D53). `radio-card.tsx` is type-checked in CI by
`scripts/check-registry-types.mjs` like every other registry wrapper.

## Tokens

`radio-card` reuses the whole `choice-card/*` token family `checkbox-card`
established — `choice-card/{size}/padding`, `choice-card/{size}/
indicator-offset-top` (the same optical-alignment nudge Alert's icon and
CheckboxCard's indicator both use), and `choice-card/selected/
{background,border}` for the checked card treatment. Only the indicator
itself differs from `checkbox-card`: it reuses Radio's own `radio/{size}/
box-size` sizing and its "light box + centred dot" convention (the box
stays `surface/default` even when checked — the border and a dot,
`calc(indicator-size / 2)`, carry the brand colour — unlike Checkbox's
solid fill) rather than a filled square with a tick.

## Notes

- **`RadioCard` (the group) has no props of its own beyond the headless
  ones.** No `orientation` default is set — pass it explicitly to match
  whatever layout (row, column, grid) you compose `RadioCardItem`s into,
  so keyboard arrow-key navigation tracks what's on screen.
- **The indicator circle is always rendered; only the dot is conditional.**
  Same reasoning as `checkbox-card`: the headless `RadioCard.Indicator`
  unmounts entirely while unchecked, so the bordered circle itself is a
  plain `<span>` (always present) with the headless `Indicator` (holding
  just the dot) nested inside.
- **Not composed from the registry `checkbox`/`radio` components.** Those
  are built around a **native `<input>`** whose visual state is driven by
  real `:checked`/`:indeterminate` CSS pseudo-classes via sibling
  selectors. `RadioCard.Item` is a `<button role="radio">` with no native
  input anywhere in its DOM — only a `data-state` attribute — so nesting
  the real `Radio` component (a `<label>` wrapping a hidden `<input>`)
  inside it would be both redundant and invalid HTML (a label/input pair
  inside a button). The indicator here is hand-built instead, mirroring
  Radio's exact visual convention but keyed off `data-state`.
- **No `asChild`.** Like `Alert`/`Chip`/`CheckboxCard`, the multi-part
  indicator/title/description anatomy doesn't compose with `asChild` the
  way a single wrapping element does.
- **No layout prop.** Stacking Items vertically, in a row, or in a grid is
  deliberately left to composition (`Stack` or a plain grid wrapper), not
  baked into either component. See the "CheckboxCard, RadioCard —
  exploration" Figma page for the design record.
