# `stack` — registry entry

The artefacts `primitiv add stack` resolves and copies into a consumer repo —
the **Flexbox stack** layout primitive from RFC 0022. Like `prose`, `stack`
has **no headless `@primitiv-ui/react` counterpart**: `<Stack>` carries zero
interactive behaviour, so it ships entirely from the registry.

## No Figma counterpart

There is deliberately **no Figma component set** for this primitive, and none is
planned — confirmed by a sweep of every page in the Primitiv Design System file
(the `---- LAYOUT ----` section holds only `Divider`). It renders no visual
affordance of its own: everything it does is layout behaviour that Figma
expresses natively through auto-layout, so a component set would encode
nothing a designer could use. There is therefore nothing to cross-check its
tokens or variant axes against — RFC 0022 (§5, §8, §9) is its whole spec, and
the `Figma` column of `ROADMAP.md` reads `—` for exactly this reason.

## What it does

`Stack` arranges its children in a column (default) or a row via Flexbox,
with a `gap` prop resolved against a dedicated, density-scaled
`stack/gap-*` Context token per step — **never a raw px value**. It
directly continues RFC 0016's "`gap` is the tool for component-internal
spacing," generalised into a component instead of ad hoc CSS per consumer.

- `direction` — `"column"` (default) | `"row"` | `"column-reverse"` |
  `"row-reverse"` — the four `flex-direction` keywords directly.
- `gap` — `"none" | "xs" | "sm" | "md" | "lg" | "xl"` (default `"md"`). Each
  step except `none` is its own density-scaled Context token
  (`--primitiv-stack-gap-{xs,sm,md,lg,xl}`), so the gap re-tightens under
  `[data-density]` the same way every other spacing knob in the system
  does; `none` pins the flat `space-space-0` primitive (zero has no density
  curve to scale).
- `wrap` — `"nowrap"` (default) or `"wrap"`. `nowrap` is the CSS default — a
  row may overflow its container rather than break onto additional lines.
  Opt into `wrap` for a row that must never overflow (e.g. a row of buttons
  that needs to survive a narrow viewport).
- `align` — `"start" | "center" | "end" | "stretch" | "baseline"` (default
  `"stretch"`). Cross-axis alignment (`align-items`), as a modifier class.
- `justify` — `"start" | "center" | "end" | "between" | "around" | "evenly"`
  (default `"start"`). Main-axis distribution (`justify-content`), likewise a
  modifier class.

### Why these are presets, not raw CSS keywords

The first build passed `align`/`justify` straight through as **inline styles**,
reasoning that Flexbox keywords aren't design tokens so there was no enum to
drive a `cva` variant from. That was wrong twice over: there *is* a natural
finite set, and a component that writes a `style` attribute has an
under-designed API — it hands the consumer a channel for arbitrary CSS, and it
makes the rendered result impossible to reason about from the class list alone.

`Stack` now writes **no `style` attribute at all**. The trade is that exotic
values (`align="safe center"`, `justify="stretch"`) are gone; a layout needing
one of those is bespoke enough to belong in the consumer's own stylesheet,
where it can override `align-items` on the element directly.

## Usage

```tsx
import { Stack } from "@/components/stack";

<Stack gap="sm">
  <Field />
  <Field />
</Stack>

<Stack direction="row" gap="xs" align="center">
  <Avatar />
  <span>Jane Cooper</span>
</Stack>
```

Render your own semantic element via `asChild`:

```tsx
<Stack asChild direction="row" gap="md">
  <nav aria-label="Breadcrumb">...</nav>
</Stack>
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-stack` root class, the `--row`/`--column`/`--row-reverse`/`--column-reverse`, `--gap-*`, `--nowrap`/`--wrap`, `--align-*` and `--justify-*` modifiers, and the `--primitiv-stack-gap` custom property. |
| `styles.css` | **authored** | The canonical default theme: the Flexbox rules + gap steps, in `@layer primitiv.base`/`primitiv.variants`. |
| `styles.scss` | **authored** | `styles.css` plus a trailing `$`-alias block, one `$primitiv-stack-<prop>` per custom property. |
| `stack.recipe.ts` | **authored** | `cva("primitiv-stack", { variants: { direction, gap, wrap, align, justify } })`. |
| `stack.tsx` | **authored** | The `<Stack>` wrapper. Hand-written (there is no primitive to generate from): resolves all five modifiers through the recipe. Writes no `style` attribute. |

Because there is no headless primitive, `stack.tsx`/`stack.recipe.ts` are
**not** generated by `primitiv-emit` and carry **no drift-guard test**
(contrast the generated wrappers, D53). `stack.tsx` is type-checked in CI by
`scripts/check-registry-types.mjs` like every other registry wrapper.

## Tokens

`stack` owns `--primitiv-stack-gap` (the component's own API knob, re-pointed
by the `gap` modifier to one of the five density-scaled
`--primitiv-stack-gap-{xs,sm,md,lg,xl}` Context tokens — a new family added
for this component, sized proportionally against the existing `space-*`
scale). `align`/`justify` own no custom properties — they are plain modifier
classes setting `align-items`/`justify-content` directly. See RFC 0022 §3.
