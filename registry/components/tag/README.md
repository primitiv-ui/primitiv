# `tag` — registry entry

The artefacts `primitiv add tag` resolves and copies into a consumer repo —
the **label chip** from RFC 0021. Like `badge`, `tag` has **no headless
`@primitiv-ui/react` counterpart**: `<Tag>` carries zero behaviour, so it
ships entirely from the registry.

## What it does

`Tag` renders a `<span>` chip that tags content by category, topic, or
status — typically shown in a horizontal group (e.g. `Design`, `Rust`).
Read-only, never interactive. Five tones, sized `xs`–`xl` (default `md`);
`data-density` scales each size further.

| Tone | Typical use |
|---|---|
| `neutral` (default) | a plain label — the common case |
| `success` / `warning` / `info` / `danger` | status, e.g. "Shipped" |

Unlike `Badge`, a Tag has **no `variant` axis** — it is always the
low-emphasis tinted treatment (`feedback/{tone}/soft/*`; there is no
solid/counter equivalent) — and **no circularity trick**: `min-inline-size`
is left unbound, so a Tag simply hugs its content width regardless of
length.

## Usage

```tsx
import { Tag } from "@/components/tag";

<Tag>Design</Tag>
<Tag>Rust</Tag>
<Tag tone="success">Shipped</Tag>
```

## Files

| File | Authored? | Role |
|---|---|---|
| `contract.json` | **authored** | The styling contract — the `.primitiv-tag` root class, the `tone`/`size` modifiers, and the `--primitiv-tag-*` custom properties. |
| `styles.css` | **authored** | The canonical default theme: the chip box + tone colour matrix, in `@layer primitiv.base`/`primitiv.variants`. |
| `styles.scss` | **authored** | `styles.css` plus a trailing `$`-alias block, one `$primitiv-tag-<prop>` per custom property. |
| `tag.recipe.ts` | **authored** | `cva("primitiv-tag", { variants: { tone, size } })` — mirrors `badge`'s recipe shape. |
| `tag.tsx` | **authored** | The `<Tag>` wrapper. Hand-written (there is no primitive to generate from): a thin `asChild` (Slot) wrapper that renders a `<span>`, or the consumer's own element. |

Because there is no headless primitive, `tag.tsx`/`tag.recipe.ts` are **not**
generated by `primitiv-emit` and carry **no drift-guard test** (contrast the
generated wrappers, D53). `tag.tsx` is type-checked in CI by
`scripts/check-registry-types.mjs` like every other registry wrapper.

## Tokens

`tag` reuses Badge's `feedback/{tone}/soft/{background,foreground}` Intent
tokens directly (including a `feedback/neutral/soft/*` entry Badge doesn't
use — Tag's most common real-world case is a plain grey label), plus its own
sizing family:

- **`tag/{size}/{height,padding-inline,font-size,line-height,gap}`** (Context)
  — sizing, density-scaled. `font-size` and `line-height` are Tag's own scale
  (2026-07-30), like Badge's `badge/{size}/font-size` — `body/{size}`'s own
  scale is flat at Dense (10/11/12/13/14, barely distinguishable across
  sizes, the same problem Badge had), so Tag needed a dedicated scale there.
  `line-height` was decoupled from `body/{size}/line-height` the same day:
  once `font-size` stopped tracking `body/{size}`, that pairing broke —
  several size/density cells ended up with a real vertical gap
  (`height - line-height`) of zero or negative. `gap` is reserved for a
  future leading-indicator slot the current single-child anatomy doesn't
  consume.

Typography is `tag/{size}/font-size|line-height` + `body/{size}/font-family
|font-weight` — a Tag reads as a plain label, not a stat, so it tracks
surrounding body text's family/weight rather than Badge's Khand SemiBold,
while still needing its own size/line-height scale for density contrast.
